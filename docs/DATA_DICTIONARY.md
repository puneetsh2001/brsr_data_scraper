# Data dictionary (Phase 15)

Generated by `python -m app.reporting.data_dictionary` from
`app/reporting/data_dictionary.py`. A test fails if an output
column is undocumented or this file is out of date.

All files are UTF-8 CSV (with BOM), written to `data/outputs/`, with
`manifest.json` holding the SHA-256 and row count of every file and
of every source.

## General rules

- Values are copied from approved outputs; nothing is recalculated.
- A blank cell means missing / not reported. It is never zero.
- Explicit zeros reported by a filer stay `0` (REPORTED_ZERO).
- Pending, deferred, candidate and unresolved records are kept and
  labelled; pillar files contain all applicable rows.
- Recommendations are not approvals; `approval_decision`, 
  `reviewer_decision` and `unit_decision` show what was decided.
- Assessment, Assurance, Limited and Reasonable assurance are
  separate values and never merged.
- Supplementary PDF evidence covers Reliance only and is shown as
  unverified candidates; it never replaces XBRL values.

## Status vocabularies

### coverage_status

| Status | Meaning |
|---|---|
| `REPORTED` | a non-zero CY value was extracted from XBRL |
| `REPORTED_ZERO` | the filer reported the value 0 (an explicit zero) |
| `REPORTED_PENDING_CROSSWALK_REVIEW` | values exist only through a candidate crosswalk mapping awaiting review; not counted as reported |
| `NOT_DISCLOSED` | the concept exists in the filing's taxonomy version but the filing has no CY fact for it (PY-only facts do not count) |
| `EXTRACTION_ERROR` | evidence of a pipeline failure: the filing exists but could not be downloaded or parsed, or a CY fact is present but no value was selected |
| `NOT_IN_TAXONOMY_VERSION` | the filing's taxonomy version has no concept for this metric |
| `NO_REPORT` | no BRSR filing in this FY slot |
| `EXTERNAL_SOURCE_REQUIRED` | metric is not in BRSR XBRL (annual report, MCA, etc.) |
| `NOT_APPLICABLE` | applicability concept says the metric does not apply |

Missing information is never inferred from the absence of a local PDF.
`EXTRACTION_ERROR` needs evidence (failed download / parse, or a CY fact
present but unselected).

### record_status (precedence top to bottom)

| Status | Meaning |
|---|---|
| `DEFERRED_DATA_QUALITY_ISSUE` | linked to an open deferred issue (DQ-xxx) |
| `PENDING_CROSSWALK_REVIEW` | value from a candidate crosswalk mapping |
| `PENDING_SCALE_REVIEW` | filer scale-error record pending; original value kept |
| `PENDING_UNIT_DECISION` | unit assumption awaiting approval; not converted |
| `NOT_NORMALISED_UNIT_AMBIGUOUS` | unit could not be determined |
| `NOT_NORMALISED_PERCENT_SCALE_AMBIGUOUS` | percent vs fraction unclear |
| `NOT_NORMALISED_TEXT_TYPE` | text in a numeric concept |
| `TEXT_VALUE` | text concept; no normalisation applies |
| `NORMALISED_APPROVED_UNIT_DECISION` | converted under an approved unit decision |
| `NORMALISED_APPROVED_SCALE_CORRECTION` | converted under an approved scale correction |
| `NORMALISED_FROM_XBRL` | converted by rule or no conversion needed |

### validation_status

| Status | Meaning |
|---|---|
| `FAILED_RULES` | at least one Phase 9 rule failed for this value |
| `OPEN_REVIEW_ITEMS` | no failure, but open review recommendations |
| `NO_FAILURE_RECORDED` | no failed rule and no open review item (not a verification) |

Review workflow statuses: DETECTED | RECOMMENDED | PENDING_REVIEW | APPROVED | REJECTED | DEFERRED | APPLIED.
