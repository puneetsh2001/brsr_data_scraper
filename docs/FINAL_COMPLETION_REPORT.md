# Final completion report

Date: 2026-11-13 (end of Phase 17).

**Scope:** SEBI BRSR data from NSE XBRL, for the Nifty 100 companies and the
FY slots 2021-22 to 2025-26.

All figures below were measured on the project files at the end of Phase 17.

## 1. Result

The platform runs end to end from local data, through the single CLI
(`python -m app.pipeline`). It produces the 20 deliverables of the master
prompt, plus a company-year coverage summary and a manifest, and it is
covered by 500 automated tests.

**Re-run check.** A full re-run of every processing and validation stage was
made in an isolated copy of the project. It reproduced all 975 project data
files byte for byte, apart from two run timestamps. The re-run took 468 s for
the 11 stages and 58 s for the report.

**Independent validation.** A separate checker shares no code with the
pipeline. It passed all 20 of its checks on both the accepted outputs and the
re-run outputs.

Approved values, pending decisions and deferred issues are unchanged. The
production database was never written.

## 4. Phase 17 evidence

### 4.1 Full pipeline run in isolation

The re-run was made in a copy of the code and data in a scratch folder. The
copy had no `.env`, so no database could be reached. It ran
`reprocess-full-corpus --execute`, which ran all 11 stages forced, and then
`report`.

- 973 of 975 data files were byte-identical.
- The other two files differ only in their timestamps:
  - `manifest.json` (`generated_at`): the output hashes and source hashes are
    identical;
  - `pipeline_state.json` (`ran_at`): all 11 stage fingerprints are identical.
- The data dictionary generated by the run is identical to
  `docs/DATA_DICTIONARY.md`.
- The SHA audit of the real project, taken before and after the run, shows
  that the accepted data was not touched.

### 4.2 Defect found and fixed

**What the re-run first showed.** The first re-run differed in 35 reason
texts. These are the `A31_SCOPE_UNIT_TAGS_DIFFER` reasons, in
`review_workflow/anomalies.csv`, `review_queue.csv` and
`data_quality_report.csv`.

**Cause.** The scope tags were listed in Python set order, which depends on
`PYTHONHASHSEED`. The values, IDs and statuses were the same; only the text
order differed.

**Fix.** `app/review/anomaly_engine.py` now lists the tags in sorted order.
This is the order in the accepted output, so no accepted file changed. The
original file is backed up.

**Verification.**

- The outputs are identical to the accepted files under four hash seeds.
- After the fix, the full re-run is byte-identical apart from the two
  timestamps.
- The regression test is `tests/test_phase17_determinism.py`. The old code
  gave 5 different text orders across 6 seeds.

### 4.4 Tests

The full suite has 500 tests, all of which pass. It includes 2 new
determinism tests. The suite runs with the integrity guard switched on, which
hashes `data/outputs`, `data/reference`, `data/processed` and `data/raw` at
the start and end of the session.

## 5. Open owner decisions (unchanged by design)

- **Filer scale-error records:** 39 are pending. 25 are recommended APPROVE
  and 14 DEFER. A block that is only partly corrected (`BLOCK_PARTIAL`) can
  only be decided as a whole.
- **Deferred data-quality issues:** 39 are open. They block any production
  import.
- **Unit assumptions:**
  - 474 MtCO2e assumptions are pending review;
  - 35 are undetermined;
  - 20 are flagged because the restatement differs;
  - 55 are approved and applied.
- **Crosswalk:** 7 candidate mappings, covering 230 cells, are pending. V01
  equivalence is not approved.
- **Assurance findings:** 9 AS02 and 2 AS08 issues are unresolved. The 38
  AS07 informational findings are preserved.
- **`kgCO2e`:** there is no conversion rule. No filing uses the unit, and no
  source defines its measure name.

## 6. Limitations and gaps

- **API.** The query API in master prompt area 13 (metric, comparison and
  quality queries) is not implemented. `app/api/brsr_routes.py` and
  `dashboard_routes.py` are empty, and `company_routes.py` predates the
  project. The API was not part of the 17-phase plan, so it needs a decision
  on whether to schedule it.
- **External sources.**
  - The BSE API and the MCA portal return HTTP 403 to automated access. BSE
    is covered by a manual-import path.
  - MCA validation through data.gov.in needs an API key.
- **Supplementary PDFs.** Only Reliance documents are local. The 417 NSE BRSR
  PDF URLs are recorded but not downloaded, by owner decision.
- **Failed filings.** Two in-scope filings could not be extracted: an HTTP 404
  and a malformed XML file. Their 192 coverage cells are labelled
  `EXTRACTION_ERROR`.
- **Selective reprocessing.** Per-company or per-FY reprocessing is not
  supported, because the outputs are corpus-wide and several rules compare
  years. Use `reprocess-full-corpus`.
- **Production database.** The import has not been performed. It needs:
  - owner approval;
  - all deferred issues resolved;
  - `PRODUCTION_WRITES_ENABLED` changed.
